Chat replay beside the player: messages synced to the playhead, shifted by the viewer's Chat sync offset and set in their chat typography from Settings, with a jump back to the current time. A JS-owned island.

## Build it from

Keep `ChatPane.razor.js` owning the log, polling, auto-scroll and the open state. Restyle to match an outlined `MudPaper`:

- Open on desktop: the right-hand column of the watch view, `flex: 0 1 400px` with a `chat-width` (320px) minimum, so it widens on wide screens. It takes all the vertical space of the view, from the top of the main column to the bottom of the viewport, sticky while the left column (player, title block, Chapters, Stats) scrolls; everything else stays to its left (see `AppShell`). The log fills the height between the header and the bottom, or between the header and the footer while the viewer is behind, on `drawer-background`, `radius-lg`, `lines-default` outline. The header has the `Chat` icon (decorative, `action-default`), "Chat replay" in `subtitle1`, and one decorative state icon in `caption`, no larger than 20px and in the state's colour: `HourglassEmpty` loading, `Wifi` live (`primary`), `Sync` spun clockwise while reconnecting (`warning`; static under `prefers-reduced-motion: reduce`), `Schedule` waiting for chat, `SpeakerNotesOff` no chat captured, `History` replay, `CloudOff` unavailable and `WifiOff` disconnected (both `error`). Each state's accessible wording lives in a visually hidden label and the tooltip: "Loading chat…", "Chat connected", "Reconnecting", "Waiting for chat…", "No chat captured", "Chat replay", "Chat unavailable" and "Chat disconnected". The icon is decorative (`aria-hidden`), so no state depends on colour alone; `role="status"`/`aria-live="polite"` announce the label change. Reconnecting shows only when chat exists; a reconnecting session with no chat keeps "Waiting for chat…".
- Log: `body2`, with the offset in `timecode` (11px, `text-secondary`), the name in 700 weight, and replies quoted in `caption` behind a `divider` rule. *As built in #180 rows show no offset yet: adding it would change the log's content, which the issue does not cover.*
- **Footer**: the centered "Jump to current time" pill, rendered only while the viewer is behind the newest row; there is no footer element, border, padding, or reserved height while following, and none for an unavailable or not-yet-captured chat. The `(N)` count appears when new messages arrived. A notice row between the log and the footer carries load errors, hidden when empty, so an error never keeps the footer alive; it is the visible error surface below `Md`, where there is no header. Chat sync is no longer here: it is one offset for every recording, set in Settings › Chat (`ChatSettings`), and the pane applies it to every fetch.
- **No toggle of its own.** The player's Chat button (see `VideoPlayer`) and `C` open and close the pane; the header is a plain title. Closed, the pane is not shown at all: no strip is left behind, and the player takes the sidecar's width.

## Rules

- The streamer's own messages take their channel colour (`channel-*`). Other chatters' names use their Twitch colour only where it reaches 4.5:1 on `surface`; otherwise `text-primary`.
- Each row may open with the text chips that stand in for badges (MOD, SUB, VIP…), labelled from the badge set. Settings › Chat's "Show badge text" (`UiPreferences.ChatShowBadgeText`, on by default) hides them in every pane through the root's `data-badge-text` and `display: none`, so they leave the layout and the accessibility tree. Badge images are a separate, unbuilt surface and are not gated by this switch.
- Settings › Chat's font size (85–145% of `body2`, default 100%) and font weight (400/500/700, default 400) apply to every pane. The log's message text and names take the size; names stay 700; replies and gaps keep `caption`, badge chips keep `label`, and emote images are `2em` (28px at 100%). The pane root carries `--sk-chat-font-scale` and `--sk-chat-font-weight`; a change applies live without a refetch or a log rebuild.
- In theater mode it moves below the player and stays the right-hand column there, taking the height left down to the bottom of the viewport, at least 260px (see `TheaterMode`).
- Below `Breakpoint.Md` it is the **Chat** tab under the player (`MudTabPanel Icon="@Icons.Material.Rounded.Chat"`), filling the rest of the screen without its own header; the tab owns the disclosure, so the pane is always open.
- The channel colour comes from .NET (`ChannelColor`) in the pane's payload (`channelLogin`, `channelColor`), so chat and the drawer always agree (player contract §10a).
- Links in message and reply text use `primary` with an underline; long URLs wrap inside the log's `overflow-wrap: anywhere`. Only absolute `http(s)` URLs link, and the visible text stays as typed.
